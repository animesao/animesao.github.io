# AGENTS.md — Developer & AI Agent Guidelines

Этот документ описывает архитектуру, структуру каталогов, ключевые соглашения и правила разработки кодовой базы персонального сайта-портфолио **animesao**. Любой последующий AI coding agent или инженер обязан соблюдать эти правила.

---

## 1. Архитектурный стек и структура директорий

Проект реализован на **Nuxt 4.6.x** с использованием актуальной структуры директорий `app/` (согласно соглашениям Nuxt 4, где исходный код приложения изолирован в каталоге `app/`).

## 2. Ключевые команды

| Команда | Описание |
|---|---|
| `pnpm install` | Установка зависимостей через pnpm |
| `pnpm run dev` | Запуск локального dev-сервера на `http://localhost:3000` |
| `pnpm run generate` | **Основной способ сборки:** Статическая генерация сайта (SSG) в `.output/public` |
| `pnpm run build` | Сборка SSR/Node-сервера (Nitro preset: `node-server`) |
| `pnpm run typecheck` | Проверка типов TypeScript через `nuxt typecheck` / `vue-tsc` |
| `pnpm run lint` | Проверка линтером ESLint с Nuxt-правилами |
| `pnpm exec eslint . --fix` | Автоматическое исправление стиля кода |

## 3. Критические правила для последующих AI-агентов

### 3.1. Достоверность данных (Truthfulness Rule)
- **НЕЛЬЗЯ** выдумывать компании, звания (CTO, Lead Architect корпораций), возраст, образование, сертификаты или годы опыта для `animesao`.
- **НЕЛЬЗЯ** выдумывать фальшивые метрики проектов (количество звёзд, загрузок, бенчмарки скорости, клиентов).
- **НЕЛЬЗЯ** представлять планируемые проекты (например, `@cardinal-panel` на PHP/Laravel) как завершённые релизы. Они обязаны иметь статус `'planned'` и честное описание.
- **НЕЛЬЗЯ** придумывать профили в соцсетях, телефоны или email. Только подтверждённые ссылки из `app/data/links.ts`.
- **НЕЛЬЗЯ** генерировать фиктивные статьи блога. Если реального контента нет, раздел заметок должен оставаться в нейтральном состоянии «в подготовке».

### 3.2. Разделение контента и представления
- Весь контент (тексты, описания, технологии, ссылки, статусы) хранится в `app/data/`.
- Компоненты разметки (`app/components/` и `app/pages/`) должны оставаться переиспользуемыми шаблонами, получающими данные из `app/data/` и функции `useI18n()`.
- Никогда не хардкодьте длинные текстовые блоки прямо в разметку компонентов без поддержки двуязычия.

### 3.3. Двуязычие (i18n)
- Проект использует `@nuxtjs/i18n` с префиксной стратегией (`prefix_except_default`):
  - Русский язык — по умолчанию на корневых URL (`/`, `/about`, `/projects`).
  - Английский язык — с префиксом `/en` (`/en`, `/en/about`, `/en/projects`).
- Внутренние ссылки в компонентах обязательно оборачивать в `localePath('/path')`.
- Переключение языка выполняется через `switchLocalePath('ru')` и `switchLocalePath('en')`.

### 3.4. Стилизация и Tailwind CSS 4
- Используется Tailwind CSS 4.x. Кастомные классы утилит должны регистрироваться через `@utility <name>` в `app/assets/css/main.css`, чтобы валидатор `eslint-plugin-better-tailwindcss` не выдавал ошибки.
- Эстетика: монохромная, графитовая, высококонтрастная sci-fi эстетика без ядовитых фиолетовых/синих градиентов, избыточного блура или тяжелых 3D-библиотек.
- Доступность: обязательно сохранять `:focus-visible` контуры и соблюдать `@media (prefers-reduced-motion: reduce)`.

### 3.5. Шрифты и внешние зависимости
- В `nuxt.config.ts` в блоке `fonts.providers` отключены внешние сетевые загрузки Google, Fontsource, Bunny, Adobe во время сборки. Шрифты полагаются на системный стек и локально закешированные шрифты.
- Не подключайте внешние CDN, блокирующие запросы или непроверенные трекеры аналитики.

### 3.6. Проверка перед сдачей задачи
Перед завершением любых модификаций агент обязан последовательно выполнить:
1. `pnpm run lint` — код должен быть чист (0 errors, 0 warnings).
2. `pnpm run typecheck` — строгая проверка типов TypeScript должна завершаться успешно.
3. `pnpm run generate` — генерация статического сайта обязана проходить без ошибок, создавая `.output/public`.
